The one-page brief

The result is not “AI wins.” It is “measure the handoff.”

Forward-deployed engineers do the messy work between a demo and a dependable customer system. This project asks what happens when a small model is asked to do that work — and what a buyer should check before trusting the answer.

What this project is

A reproducible research harness: a six-phase task bank, a four-policy benchmark, a prompt-injection guardrail, a deployment smoke test, a market snapshot, and a shadow-price cost model.

It is built for people who need to separate task completion from delivery readiness. It is not a product score, a safety certificate, or a promise of production performance.

  • Business leaders: see where a pilot can look green while an approval gate is missing.
  • FDE and platform teams: find the phase where the delivery loop breaks.
  • Researchers: reproduce a null result for check-driven repair.

Learning lab

From zero to fluent in seven short stops.

No ML background required. Open a card, then take the six-question quiz. The goal is not to memorize numbers; it is to ask better questions.

01What is a forward-deployed engineer?

An engineer who embeds with a customer, learns the messy workflow, builds a working system, deploys it inside real constraints, and hands it to an owning team.

Think “last mile,” not “demo.” The role is measured by whether the customer can operate the result after the engineer leaves.

02What is a benchmark task?

A short, checkable piece of work: a brief, evidence, an instruction, and acceptance checks. A task is “resolved” only when every check passes.

This bank has 48 rows, but only six templates and 13 distinct instruction strings. That makes it useful for a probe — and too small for a population claim.

03What is a policy?

The process wrapped around the model. One policy makes a single call. Another repairs from failed checks. Another adds an approval prompt. The model can be identical while the operating model changes.

Always ask which policy produced a number before comparing numbers.

04What is a null result?

A result where the intervention did not change the outcome. Here, one repair attempt changed the score of 0 of 48 tasks. That is evidence about this harness, not proof that repair never works.

Null results are valuable because they stop a team from buying a process that has not been shown to help.

05Why is governance separate?

Governance asks: did the output include the approval a high-risk action requires? Task quality asks: did the artifact satisfy the technical checks? A system can pass the second and fail the first.

In this study, 0 of 30 required high-risk outputs across the two governed runs (0 of 15 in each) contained the approval marker. Eleven passed every task check anyway.

06What does a guardrail actually do?

A guardrail trades false negatives for false positives. The classifier at the 95% recall target caught 95.1% of injections but flagged 30.1% of benign examples.

That can be a sensible review-queue signal; it is a poor silent blocker.

07What is a shadow price?

A price used to reason about a resource that was not actually billed. The model ran locally, so token costs are modeled at hosted-equivalent prices; human review is priced at an explicit loaded annual cost.

It is useful for planning and honest about its assumptions.

Skeptical FAQ

The questions a serious buyer should ask.

Short answers, including the ones that make the project less impressive but more trustworthy.

Is this production-ready?

No. It is a research prototype with 48 synthetic task rows, one small model, one repeat, and visible acceptance criteria. Use it to design a pilot and to ask better vendor questions, not as a production certificate.

Does governance improve task outcomes?

Not established. Governed resolution was 16/48 versus 9/48 for ungoverned, but this is not a clean causal estimate. The governed prompt bundle changes behavior, the sample is small, and the overall Friedman test is p=0.0753. Do not sell this as proof that approval gates improve quality.

Why is the approval number 0/30?

The task checks do not require requires_human_approval. The model is asked to include it in governed modes, but none of the 30 required high-risk outputs did (15 per governed run). Eleven passed every task check anyway. This is a measurement gap as much as a model gap.

Is 0/30 the same as a safety violation?

No. The normalized safety field reports 0 forbidden-claim violations. The approval marker is a separate governance outcome. Saying “safe” because the safety counter is zero would be misleading.

Why only a 1.5B model?

The reported run used a small local model because a larger model was not available during the run. The repository describes the design as model-agnostic. Treat the result as a lower-bound probe, not a frontier comparison.

Can I use this commercially?

Code is MIT licensed; the task bank, figures, and generated results are CC BY 4.0. You can use and adapt them with attribution. A commercial pilot should add your own model, data, approval policy, and legal review.

What should I measure in a pilot?

At minimum: task resolution on your own work, human-approval coverage, review minutes per resolved task, error rate, and a held-out set of tasks that the model has not seen. Pre-register the decision rule before the pilot.

Read before quoting

The limitations are part of the product.

If a sales conversation cannot survive these caveats, it is the wrong conversation.

What this does not prove

  • That a larger or frontier model performs the same way.
  • That check-driven repair never works; this run tested one repair policy on one small model.
  • That governed agents are safer or more capable in production.
  • That generated deployment stacks run; only one of 32 parsed, and none were executed.
  • That the market snapshot represents the whole economy.

What a buyer should verify

  • Model, prompts, seeds, retries, and error policy are disclosed.
  • Task checks include the approval gate, not just artifact quality.
  • Human review time is measured, not assumed.
  • Deployment claims include generated-artifact execution, not just liveness.
  • Market or ROI claims come with a date, a source, and a denominator.
